SHA-256: the math behind every ID

One-way function. Any input → a fixed 256-bit fingerprint. Change one character and the whole output changes.

Unique coin / transaction ID

txId = SHA256( from + to + amount + timestamp )

Because timestamp is in milliseconds and SHA-256 has 2256 outputs, two IDs colliding is practically impossible.

Wallets = key pairs

privateKey → (elliptic curve math) → publicKey
address = + SHA256(publicKey)[0..40]

Private key signs, public key verifies. You can't go backwards from public to private.

Genesis block

Block #0 is hard-coded. Every later block points to the hash before it.

blockHash = SHA256( index + prevHash + timestamp + transactions + nonce )

Balances (computed from the chain)

No one "stores" a balance. It's the sum of every transaction on the chain for that address.

Why it can't be copied

1. Coins only appear through a coinbase transaction inside a mined block.
2. Each block contains the previous block's hash, so blocks are chained.
3. Edit any old block → its hash changes → every later link breaks → you'd have to re-mine all of them faster than everyone else.
